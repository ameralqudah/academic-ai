# Academic AI Research Assistant

منصّة أكاديمية متخصصة تساعد الطلاب والباحثين على اختيار عناوين أبحاثهم، وبناء خطة بحث كاملة،
وكتابة الأبحاث والرسائل الجامعية خطوة بخطوة — بالعربية والإنجليزية.

A bilingual (Arabic RTL / English LTR) academic research workspace built with Next.js, TypeScript,
Tailwind CSS, Drizzle ORM and PostgreSQL.

## التشغيل السريع · Quick start

```bash
# 1) المتطلبات: Node.js 20+ و PostgreSQL 14+
npm install

# 2) الإعدادات
cp .env.example .env
#   - DATABASE_URL  → رابط قاعدة بيانات PostgreSQL
#   - AUTH_SECRET   → openssl rand -base64 32

# 3) إنشاء الجداول
npm run db:push          # للتطوير السريع
# أو
npm run db:migrate       # لتطبيق ملفات الهجرة في drizzle/

# 4) بذر الخطط (FREE و PRO)
npm run db:seed

# 5) التشغيل
npm run dev              # http://localhost:3000  →  يعيد التوجيه إلى /ar
```

لإنشاء حساب مدير أثناء البذر، اضبط `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` في `.env` قبل الخطوة 4.

## البنية · Architecture

```
src/
├─ app/[locale]/          الصفحات — مجموعات: (marketing) (auth) (app) (admin)
├─ app/api/               معالِجات الـ API — رقيقة، بلا منطق أعمال
├─ components/            الواجهة: ui/ marketing/ app/ projects/ auth/ settings/
├─ config/                env · plans · research  ← مفردات المنتج الأكاديمية
├─ i18n/                  routing · request · navigation
├─ lib/                   أدوات مشتركة (نصوص، تسجيل، أقسام)
├─ proxy.ts               حلّ اللغة فقط (كان اسمه middleware قبل Next 16)
└─ server/
   ├─ db/                 schema.ts (Drizzle) · seed.ts
   ├─ repositories/       المكان الوحيد الذي يُستدعى فيه Drizzle
   ├─ services/           منطق الأعمال — لا يعرف شيئًا عن HTTP
   ├─ auth/               Auth.js v5 + الحُرّاس
   ├─ validation/         مخططات Zod مشتركة مع العميل
   └─ http/               withApi · الأخطاء · تحديد المعدّل
```

**القاعدة الحاكمة:** `app/` للعرض والتوجيه، `server/services/` للمنطق، `server/repositories/`
للوصول إلى البيانات. لا يُستورَد Drizzle داخل مكوّن React، ولا يحتوي معالِج API على منطق أعمال.

### طبقات الطلب

```
Client → Middleware (locale) → Route Handler → withApi → Service → Repository → PostgreSQL
                                                            ↓
                                                      AI Service Layer → Provider (Phase 2)
```

`withApi` يقوم بخمسة أشياء بالترتيب: تحديد المعدّل، الجلسة، التحقق بـ zod، تنفيذ الخدمة،
ثم تغليف الخطأ في ظرف موحّد:

```jsonc
{ "ok": true, "data": … }
{ "ok": false, "error": { "code": "PLAN_LIMIT", "message": "…", "messageAr": "…" } }
```

## طبقة الذكاء الاصطناعي · AI layer

```
src/ai/
├─ provider.ts        العقد الوحيد الذي يعرفه التطبيق: AIProvider
├─ providers/         anthropic.ts · openai.ts · google.ts  (fetch مباشر، بلا SDK)
├─ registry.ts        يختار المزوّد: لوحة الإدارة → متغيّر البيئة → anthropic
├─ prompts/           system.ts (قواعد النزاهة) · titles.ts · wizard.ts
├─ context/           يبني لقطة المشروع بميزانية رموز محسوبة
└─ guardrails.ts      يفحص المخرجات: استشهادات · DOI · إحصاءات مفبركة
```

**تبديل المزوّد** = تغيير `AI_PROVIDER` في `.env` (أو من لوحة الإدارة لاحقًا). لا سطر واحد في
التطبيق يعرف اسم المزوّد.

المزوّدون منفَّذون بـ `fetch` مباشرة على REST APIs بدل حزم SDK: أقل اعتماديات، وسلوك بثّ موحّد،
وتحكّم كامل في احتساب الرموز والتكلفة.

**النزاهة الأكاديمية** مطبَّقة في ثلاث طبقات لا في واحدة:

| الطبقة | الملف | ما تفعله |
| --- | --- | --- |
| Prompt | `ai/prompts/system.ts` | قواعد صريحة: لا اختلاق مراجع ولا نتائج ولا ادّعاء إجراء تجربة |
| Code | `ai/guardrails.ts` | يلتقط أنماط الاستشهاد و DOI والإحصاءات ويعيدها كـ flags |
| UI | المحرر والمحادثة | تنبيه ظاهر + `verification=UNVERIFIED` لكل مرجع حتى يؤكده المستخدم |

**السياق:** `ai/context/builder.ts` يرسل مع كل طلب لقطة مضغوطة من المشروع — الأقسام التي يعتمد
عليها القسم الحالي بمقتطف كبير، وبقية الأقسام بمقتطف قصير، ضمن سقف إجمالي للأحرف. هذا ما يحقّق
الاتساق بين المشكلة والأسئلة والأهداف والفرضيات والمنهجية.

**تخزين التعليمات مؤقتًا (prompt caching):** هذه اللقطة تتكرّر في كل استدعاء، وهي أكبر بند في
تكلفة الإدخال. لذلك تُرسل كتلة التعليمات إلى Anthropic موسومة بـ`cache_control`، فتُقرأ من الذاكرة
المؤقتة في الاستدعاءات التالية بعُشر السعر تقريبًا. الكتابة الأولى أغلى قليلًا (1.25×) ثم كل قراءة
0.1× — والتوفير يظهر من الرسالة الثانية في الجلسة. رموز الذاكرة المؤقتة تُسجَّل في
`usage_tracking` وتُحتسب بسعرها الصحيح في لوحة الإدارة. OpenAI وGoogle يخزّنان ضمنيًا بلا إعداد.

## قاعدة البيانات · Database

18 جدولًا. أهم قرارين:

- **`research_projects` مقابل `research_sections`** — المشروع يحمل الهوية والإعدادات فقط،
  والمحتوى يعيش في أقسام مستقلة لكل واحد حالته وعدّاد كلماته. هذا ما يجعل «العودة لأي مرحلة»
  و«المتابعة من نفس النقطة» ممكنَين.
- **`subscription_plans` + `usage_tracking`** — لا حدود مكتوبة في الكود. الخطة صف في قاعدة
  البيانات، والاستهلاك يُجمَّع شهريًا بمفتاح `YYYY-MM` عبر استعلام واحد.

`section_key` و `tool_key` أعمدة نصّية مُنمَّطة في TypeScript وليست PG enums — إضافة قسم أو أداة
جديدة لا تتطلّب هجرة قاعدة بيانات.

## الاشتراكات والفوترة · Billing

```
src/server/billing/
├─ provider.ts   BillingProvider — أربع دوال فقط
├─ manual.ts     ManualBillingProvider — التدفّق كاملًا بلا بوابة دفع (الافتراضي)
├─ paypal.ts     PayPalBillingProvider — اشتراكات PayPal + تحقّق الـ webhook عبر PayPal
├─ stripe.ts     StripeBillingProvider — REST API + تحقّق من توقيع الـ webhook
└─ index.ts      يختار المزوّد من BILLING_PROVIDER ويتراجع إلى manual عند نقص المفاتيح
```

**التشغيل بلا بوابة دفع:** الوضع الافتراضي `BILLING_PROVIDER=manual` يجعل الترقية والإلغاء
وحدود الخطط والاستخدام تعمل بالكامل — الخطوة الوحيدة المتخطّاة هي الدفع. مناسب للتطوير والعرض،
ولا يجوز تفعيله في الإنتاج.

**التوصيل بـ PayPal (الموصى به للأردن):**

1. حساب PayPal Business + تطبيق مطوّر (Client ID / Secret) + Webhook.
2. ضع في البيئة: `BILLING_PROVIDER=paypal` و `PAYPAL_CLIENT_ID` و `PAYPAL_CLIENT_SECRET`
   و `PAYPAL_WEBHOOK_ID` (و`PAYPAL_ENVIRONMENT=sandbox` للتجربة).
3. خطة Pro تُنشأ تلقائيًا في PayPal من سعر الخطة في قاعدة البيانات، ويُخزَّن معرّفها في
   `app_settings` — تغيير السعر من لوحة الإدارة يُنشئ خطة جديدة بدل الاستمرار بالسعر القديم.
4. الأحداث المطلوبة: `BILLING.SUBSCRIPTION.ACTIVATED|UPDATED|CANCELLED|SUSPENDED|EXPIRED` ·
   `BILLING.SUBSCRIPTION.PAYMENT.FAILED` · `PAYMENT.SALE.COMPLETED|REFUNDED`.

خطة Pro لا تُفعَّل إلا عند وصول حدث موثَّق من PayPal، فالدفع الفاشل أو المهجور لا يمنح شيئًا،
والإلغاء يحفظ المدة المدفوعة حتى نهايتها ثم يهبط الحساب إلى المجانية تلقائيًا.

**التوصيل بـ Stripe (للدول المدعومة):**

1. أنشئ منتجًا وسعرًا شهريًا في Stripe.
2. ضع في `.env`: `BILLING_PROVIDER=stripe` و `STRIPE_SECRET_KEY` و `STRIPE_WEBHOOK_SECRET`
   و `STRIPE_PRO_PRICE_ID` (أو اضبط `external_price_id` للخطة من لوحة الإدارة).
3. وجّه webhook إلى `POST /api/billing/webhook` وفعّل الأحداث:
   `checkout.session.completed` · `customer.subscription.created|updated|deleted` ·
   `invoice.payment_failed`.

التوقيع يُتحقَّق منه بـ HMAC-SHA256 مع مقارنة ثابتة الزمن ونافذة تسامح ٣٠٠ ثانية.

**حدود الاستخدام** تُفحص قبل استدعاء الذكاء الاصطناعي وتُسجَّل بعده بالقيمة الفعلية
(`usage.service.ts`) — لأن عدد الكلمات المولَّدة غير معروف قبل التوليد.

## اللغتان و RTL

- مسار واحد `/[locale]/…`، والاتجاه يُشتق مرة واحدة في `app/[locale]/layout.tsx`.
- كل نصوص الواجهة في `messages/ar.json` و `messages/en.json` — لا نص مكتوب داخل مكوّن.
- التنسيق يستخدم خصائص منطقية (`ms-*`, `me-*`, `border-s-*`, `start-*`) فلا يوجد CSS منفصل للعربية.
- تفضيل اللغة يُحفظ في `users.locale` و `user_settings.preferred_locale`، فيبقى ثابتًا عبر الأجهزة.

## الخطوط · Fonts

الخطوط (`IBM Plex Sans Arabic` للنص و`Amiri` للعناوين) **مستضافة ذاتيًا** من حزم
`@fontsource` على npm، وتُستورد في `src/app/globals.css`. لا طلب خارجي عند أول رسم،
ولا اعتماد على وصول `fonts.gstatic.com` وقت البناء، وملفات woff2 تُشحن مع الحزمة.
كل ملف محدَّد بـ `unicode-range`، فصفحة بالإنجليزية لا تنزّل الوجوه العربية والعكس.

لتغيير خط: ثبّت حزمة `@fontsource` الجديدة، بدّل سطور `@import` في `globals.css`،
وحدّث `--font-body` أو `--font-display` في نفس الملف.

## الأمان · Security

- مفاتيح الـ API لا تصل إلى المتصفح أبدًا — كل استدعاء يمرّ عبر الخادم.
- `AUTH_SECRET` إلزامي، والجلسات JWT مع HttpOnly cookies.
- كلمات المرور مُجزَّأة بـ bcrypt (12 جولة).
- كل مدخلات الـ API تُتحقَّق بـ zod قبل بلوغ الخدمة.
- تحديد معدّل لكل مسار حسّاس (`register`, `project-create`).
- رؤوس أمان في `next.config.ts` (`nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`).
- كل استعلام مشروع يمرّ بفحص ملكية (`findOwned`) — لا وصول عبر تخمين المعرّف.

> تحديد المعدّل الحالي في ذاكرة العملية: على نشر متعدّد النسخ استبدل `src/server/http/rate-limit.ts`
> بمخزن مشترك (Redis / Upstash). التوقيع `consume()` هو ما يعتمد عليه باقي التطبيق.

### اختبارات المتصفّح · E2E

```bash
npm run build
AUTH_RATE_LIMIT_MAX=500 npm run test:e2e
```

تشتغل على بناء إنتاجي حقيقي (Playwright يشغّل `next start` تلقائيًا)، ولا تستدعي أي مزوّد ذكاء اصطناعي.
تغطّي: تفاوض اللغة من رأس `Accept-Language` (زائر عربي ← `/ar` باتجاه RTL، إنجليزي ← `/en`) ·
تبديل اللغة وقلب الاتجاه · الأسعار والأسئلة الشائعة · التسجيل والدخول والخروج ورسائل الخطأ ·
استجابة إعادة تعيين كلمة المرور الموحّدة · إنشاء مشروع وظهور الأقسام الـ13 · حدّ المشروع الواحد ·
المعالج · قفل الأدوات على الخطة المجانية · **منع مستخدم من فتح مشروع غيره** · حجب لوحة الإدارة
عن غير المدير (صفحةً وواجهةَ برمجة) · وعلى مقاس الهاتف: غياب التمرير الأفقي في العربية والإنجليزية،
والقائمة الجانبية، والوضع الداكن بعد إعادة التحميل.

`AUTH_RATE_LIMIT_MAX` يُرفع أثناء الاختبار لأن كل الطلبات تأتي من عنوان واحد.
ولو كانت البيئة توفّر متصفّحها الخاص، اضبط `CHROMIUM_PATH`.

## إعادة تعيين كلمة المرور والبريد · Email

```
src/server/email/
├─ provider.ts   EmailProvider — دالة واحدة: send()
├─ console.ts    يكتب الرسالة (والرابط) في السجل — الافتراضي في التطوير
├─ resend.ts     إرسال حقيقي عبر HTTP API
└─ templates.ts  رسالة إعادة التعيين بالعربية RTL والإنجليزية LTR
```

التدفّق: `/{locale}/forgot-password` → رمز عشوائي ٣٢ بايت يُخزَّن **مجزّأً بـ SHA-256** في
`verification_tokens` بصلاحية ٣٠ دقيقة → رابط في البريد → `/{locale}/reset-password`.

قرارات أمنية مقصودة: الاستجابة واحدة سواء وُجد البريد أم لا (لا تسريب لوجود الحسابات)، والرابط
يعمل **مرة واحدة فقط**، وإصدار رابط جديد يُبطل السابق، وحدّ ٥ طلبات كل ١٥ دقيقة لكل IP.

في التطوير (`EMAIL_PROVIDER=console`) يظهر الرابط في سجلّ الخادم، فيعمل التدفّق كاملًا بلا مزوّد بريد.

## لوحة الإدارة · Admin

`/{locale}/admin` — متاحة فقط لمستخدم `role = ADMIN` (الحارس في `(app)/admin/layout.tsx`،
وكل مسار `/api/admin/*` يمرّ بـ `withApi({ admin: true })`).

| التبويب | ما تفعله |
| --- | --- |
| **نظرة عامة** | المستخدمون، الجدد خلال ٣٠ يومًا، المشتركون، الإيراد الشهري، طلبات AI وتكلفتها التقديرية، ورسم يومي لثلاثين يومًا |
| **المستخدمون** | بحث وترقيم صفحات، إيقاف/تفعيل حساب، منح أو سحب صلاحية الإدارة |
| **الخطط** | تعديل السعر وكل الحدود وصلاحيات المزايا ومعرّف السعر لدى مزوّد الدفع — بلا نشر جديد |
| **استهلاك AI** | تبديل المزوّد والنماذج، والاستهلاك والتكلفة لكل مستخدم |

لإنشاء أول مدير: اضبط `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` ثم `npm run db:seed`.

## النشر · Deployment

**اتبع [`DEPLOY.md`](./DEPLOY.md)** — دليل خطوة بخطوة من صفر إلى رابط يعمل
(Neon للقاعدة + Anthropic للذكاء الاصطناعي + Resend للبريد + Vercel للاستضافة، ٢٠–٣٠ دقيقة).

باختصار: أمر البناء على Vercel هو `npm run vercel-build`، وينفّذ بالترتيب
**هجرة قاعدة البيانات → بذر الخطط وحساب المدير → بناء Next.js**، فلا أمر يدوي على القاعدة.

بعد النشر افتح `/api/health` — يعرض حالة كل اعتمادية (قاعدة البيانات، الهجرات، البذر،
مزوّد الذكاء الاصطناعي، البريد، الفوترة، تحديد المعدّل) دون كشف أي مفتاح، ويعيد
`503` بدل `200` إن كان أي منها ناقصًا.

يعمل أيضًا على أي منصة تدعم Node.js 20+ (Railway، Fly.io، Render، Docker):
اضبط المتغيّرات، ثم `npm run db:migrate && npm run db:seed`، ثم `npm run build && npm start`.

## قبل الإطلاق · Before going live

المشروع مكتمل الوظائف، وهذه القرارات مؤجَّلة عن قصد وموثَّقة هنا بدل تركها مفاجآت:

- **تحديد المعدّل** — الافتراضي `memory` وهو لكل نسخة. عند النشر على أكثر من نسخة اضبط
  `RATE_LIMIT_STORE=redis` مع بيانات Upstash. المخزن يفشل **مفتوحًا**: إن تعذّر الوصول إلى Redis
  تُسمح الطلبات ويُسجَّل تحذير، لأن محدِّد معدّل يُسقط المنتج أسوأ ممّا يمنعه.
- **بوابة الدفع** — الوضع الافتراضي `manual`. في الإنتاج يرفض منح الخطط المدفوعة ما لم تضبط
  `MANUAL_BILLING_ALLOW_PAID=true` صراحةً، فلا تتحوّل خطة Pro إلى ترقية مجانية عند فقدان مفتاح Stripe.
- **البريد** — الافتراضي `console`. في الإنتاج اضبط `EMAIL_PROVIDER=resend` مع `RESEND_API_KEY`
  و`EMAIL_FROM`، وإلا فروابط إعادة التعيين تُكتب في السجل فقط (وسيحذّرك التطبيق عند الإقلاع).
- **الخطوط** — محمّلة من Google Fonts عبر `<link>`؛ انظر قسم الخطوط للاستضافة الذاتية.
- **حدّ التسجيل** — `AUTH_RATE_LIMIT_MAX` افتراضيًا ٥ محاولات لكل IP كل ١٥ دقيقة. ارفعه إن كان
  مستخدموك خلف شبكة جامعية تشترك في عنوان عام واحد.
- **الاختبارات** — `test:smoke` و`test:integration` و`test:e2e` تغطي المنطق وطبقة الخدمات
  والمتصفّح. ما يبقى: اختبار عقد لمزوّدي الذكاء الاصطناعي مقابل استجابات مسجَّلة.
